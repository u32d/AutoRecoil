# 使用说明

本文档是 AutoRecoil 的详细使用手册，覆盖全部控件、快捷键、典型工作流与常见问题。架构与实现原理见 [architecture.md](architecture.md)。

## 环境要求

- Windows 操作系统，已安装 [.NET Framework 4.8 运行时](https://dotnet.microsoft.com/download/dotnet-framework/net48)（Win10 1903+ / Win11 一般已内置）
- 若目标程序以管理员身份运行，本工具也必须以管理员身份运行，否则注入会被 UIPI 拦截

## 典型工作流

### 1. 压枪（核心功能）

1. （可选）在 `TITLE` 输入目标窗口标题关键字，点 **F** 找到目标窗口；找到与否不影响压枪本身
2. 打开 **Move Speed** 开关（勾选，或直接按 `CapsLock`）——这是压枪总开关
3. 按住触发键（默认鼠标左键）：
   - **刚按下的第一 tick**：鼠标下移 `MoveY + RelaY` 像素
   - **持续按住期间**：每 `Speed` 毫秒下移 `MoveY` 像素
4. 松开触发键立即停止

**调参建议**：

- `Speed` 保持 1（最小循环间隔），够快且平滑
- `MoveY` 从 2–4 起步，逐步加大直到抵消上跳；不同武器灵敏度不同，需按手感微调
- `RelaY`（首发量）通常略大于 `MoveY`，补偿第一发额外的上跳
- `MoveX` 默认 10 即不偏移；若武器有水平后座再微调（<10 左偏，>10 右偏）
- `Shoot` 影响压枪平滑度：每次 tick 的位移会被拆成 `max(1, Shoot/10)` 步发送；1–9 均为单步

### 2. 连点（Auto Shoot）

1. 按 `Shift+CapsLock` 或勾选 **Auto Shoot**（勾选后文字变红）
2. 按住触发键即开始连发，松开即停
3. 连点节奏由 `Shoot` 滑块控制（两次点击的间隔毫秒数）

两种实现路径，由 `Input Mode` 决定：

- **SInput**：向系统输入队列"按住"触发键，随后周期性做一次"抬起→探测物理键状态→再按下"，因此即使合成事件也干扰不了松开检测；无需目标窗口句柄
- **SendMessage / PostMessage**：每 `Shoot` 毫秒向目标窗口投递一次完整点击（按下+抬起，坐标取当前光标位置）；**必须先用 F 找到窗口**，否则自动跳过

> Auto Shoot 与压枪可同时开启：按住触发键时既连发又压枪。

### 3. kill 宏（Send Kill）

1. 按 `Alt+CapsLock` 或勾选 **Send Kill**（勾选后文字变橙色）
2. 按一下 `` ` `` / `~`（波浪键），工具以 SendInput 逐键打出 `kill` 并回车
3. 文本内容硬编码在 `Sources/Forms/MainForm.cs` 的 `SendKillKey()` 方法中，按目标游戏的指令格式自行修改

### 4. 准星悬浮窗

- 点 **C**：准星窗口出现并对准目标窗口中心（中心带固定偏移补偿）；再点 **C** 隐藏/显示切换
- 准星窗为 128×128 无边框置顶窗，品红色底被 TransparencyKey 抠成透明，只留中心红色 `*`
- 未找到目标窗口时，准星默认对准主窗口自身中心

## 快捷键一览

| 按键 | 功能 | 说明 |
| --- | --- | --- |
| `CapsLock` | 切换 Move Speed | 压枪总开关 |
| `Shift+CapsLock` | 切换 Auto Shoot | 连点开关 |
| `Alt+CapsLock` | 切换 Send Kill | 宏开关 |
| `` ` `` / `~` | 发送 kill 宏 | 仅 Send Kill 开启时 |
| `Ctrl+CapsLock` | 无动作 | 保留给系统，工具不响应 |

热键由后台线程轮询检测、按下沿触发：无需目标窗口焦点，全局生效；CapsLock 本身的输入状态会被工具读取但不拦截，大小写状态可能随之改变。

## 常见问题（FAQ）

**Q：按住鼠标没有任何反应？**
A：检查 Move Speed 是否开启（`CapsLock` 切换，或勾选复选框）。压枪只在"Move Speed 开启 且 触发键物理按住"时生效。

**Q：Move Speed 开了，但鼠标还是不动？**
A：按顺序排查：
1. 目标程序是否以管理员运行？是的话右键"以管理员身份运行"本工具（UIPI 会拦截低权限进程对高权限进程的输入注入）
2. 检查 `recoil-diag.log` 中 `sent=` 是否为 1、光标坐标是否变化（见 [architecture.md](architecture.md) 的诊断日志一节）

**Q：游戏收不到连点 / 点击（Auto Shoot 用 Send/Post 模式时）？**
A：PostMessage / SendMessage 只对处理窗口消息的程序有效，多数游戏读 Raw Input 会直接忽略。切换到 **SInput** 模式；若用 Send/Post 模式，请确认已用 F 按钮找到窗口（hWnd 显示蓝色十六进制值）。

**Q：连点停不下来？**
A：SInput 模式采用"按住 + 周期探测物理键"的机制，只要物理键仍按住就会持续点击；完全松开后最多一个周期内停止。若异常卡住，取消勾选 Auto Shoot（合成按键会被立即抬起）。

**Q：热键不生效或乱切换？**
A：热键在后台线程轮询、按下沿触发，含 `Ctrl` 的组合被刻意忽略。若与其他软件的 CapsLock 改键工具冲突，请停用对方。

**Q：准星贴不到游戏中心？**
A：C 按钮使用硬编码偏移 `+26/+12` 补偿边框与标题栏，不同 DPI 缩放 / 窗口样式下会偏。目前准星窗口不支持拖动，如需调整请修改 `MainForm.btn_c_Click` 中的偏移量。

**Q：`recoil-diag.log` 文件越写越大？**
A：这是 TEMP-DIAG 调试日志，每次鼠标注入都会追加一行。正式使用可在 `InputLibrary.Diag` 中短路返回，或删除相关调用（见 [architecture.md](architecture.md)）。

**Q：杀毒软件报毒？**
A：模拟输入 + 轮询按键的工具行为与部分灰色软件特征相似，可能被启发式误报。请自行甄别后决定是否信任。

**Q：窗口找不到？**
A：F 按钮按"标题包含关键字"匹配顶层窗口（忽略大小写）。输入窗口标题中稳定存在的一段文字即可；全屏独占模式的游戏可能枚举不到其窗口。

## 安全提示

- 在任何在线游戏中使用本工具都可能违反用户协议并导致封号，风险自负
- 本工具不读写游戏内存、不注入游戏进程，仅使用公开的 Windows 输入 API，但这不代表不会被检测
- 建议仅在单机 / 离线环境或自建测试程序（如记事本、画图、自写 WinForms 程序）中验证功能
